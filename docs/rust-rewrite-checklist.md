# Native Rust rewrite feature checklist

Milestone 0 inventory for the scrnsvr 1.0.0 cutover. The [2026-11-23 product decisions](rust-rewrite-plan.md#product-decisions-2026-11-23) govern the checklist. The current behavior comes from the v0.10.0 implementation, [README](../README.md), [product brief](../PRODUCT.md), and [settings design](../DESIGN.md). The Rust column reflects a source inspection of the rewrite worktree, including milestone 3 work in progress. The live verification target is Hyprland on the development machine (NVIDIA, one 2560×1440 output at 120 Hz, scale 1).

Each row gives the delivery milestone and the state of the Rust code at inventory time. **Yes** means the Rust implementation covers the item, including features exercised through the opt-in renderer. **Partial** identifies a lower-level component, a spike, or a remaining cutover change. **No** means the corresponding Rust behavior is absent. For dropped items the milestone owns the removal and the Rust column records whether the final absence is already established. Verification describes what to run for the native app. A dash in the evidence column means no direct current test was found.

In the evidence column, suite names are relative to `tests/` and end in `.test.ts`. A script name starts with `scripts/`. Rust locators use the crate suffix as a path prefix, e.g. `app/saver.rs` means `crates/scrnsvr-app/src/saver.rs`. Explicitly marked **manual** checks need a person at the session.

## Gaps and maintainer decisions

- **Coverage gaps.** Add end-to-end coverage for public mode precedence and exit-code mapping, unavailable layer-shell, failed/crashed child retry, stop during startup, full rotation/reload timing, and systemd installation/restart. Legacy tests cover individual pieces of those flows.
- **Live and GPU gaps.** Automate callback-stall and display power-off recovery, input and cleanup beyond the existing live smoke, fault recovery in effect rendering, and thumbnail PNG generation/failures. Use simulated output events where practical. Multi-output, fractional/mixed scales, hotplug and Mesa stay outside the live release matrix.
- **Settings gaps.** Test the full clock controls, preview aspect and paused redraws, keyboard coverage beyond selected flows, clipboard/IME and accessibility in the real native window, and closed/hidden preview teardown. Add an import test that switches visuals before Noctalia responds.
- **Idle and output policies.** Choose how Hyprland primary is defined, what `--daemon` returns if the idle protocol is absent, whether manual and daemon launches share a single group, and how to rearm after dismissal/crash or a changed idle threshold. Specify the suspend/resume suppression window for the event-driven daemon.
- **Clock and catalog.** Confirm the fixed date/time strings and pattern behavior in `core/clock.rs`. The pattern replaces the time line including seconds and AM/PM, the date toggle still applies, and an invalid pattern falls back to defaults. Decide whether the three quiet-state visuals retain the Reactive category label.
- **Distribution and capture.** Choose a stable installed AppImage path for the service, the minimum runtime baseline, and whether CLI thumbnails use clean defaults or saved per-shader choices. Confirm whether transient capture failures should retry. Electron capture currently loads the saved config, including clock/effects. Gallery tiles are clean.
